# Superhuman Browser Use Pack

This repository contains a proof-of-concept Superhuman Pack that connects Superhuman Go to Browser Use Cloud using Browser Use's MCP server.

## What this repo contains

- `pack.ts`: the Pack definition and MCP server registration
- `package.json`: Node package metadata and scripts
- `tsconfig.json`: TypeScript build configuration
- `.env.example`: local testing placeholder env file

## Architecture overview

Browser Use exposes an MCP server at:

- `https://api.browser-use.com/v3/mcp`

The server expects a Browser Use API key in the custom HTTP header:

- `x-browser-use-api-key`

Superhuman Packs support MCP blocks and custom-header auth. The cleanest architecture is:

1. Install the Pack in Superhuman Go.
2. User connects their Browser Use API key via the Pack's `CustomHeaderToken` auth flow.
3. Superhuman sends the API key automatically as `x-browser-use-api-key` on MCP requests.
4. The Pack uses the Browser Use MCP server to expose Browser Use's available tools to the agent.

This is a direct integration, not a proxy or bridge service.

## Why this architecture is viable

The docs confirm that:

- Superhuman Packs supports `addMCPServer(...)`
- Browser Use Cloud exposes an MCP endpoint
- Browser Use Cloud authenticates with a static API key in a custom header
- A custom header token flow maps directly to the Pack auth model

## Setup instructions

1. Install dependencies:

```bash
npm install
```

2. Copy the example env file (for local checks only):

```bash
cp .env.example .env
```

3. Add the Browser Use API key in your Superhuman Pack connection flow when installing the Pack into your own account.

4. In Superhuman Go, validate the Pack is connected and that Browser Use tools are visible.

## MCP configuration

```ts
pack.addMCPServer({
  name: "Browser Use",
  endpointUrl: "https://api.browser-use.com/v3/mcp",
});
```

Authentication:

```ts
pack.setUserAuthentication({
  type: sdk.AuthenticationType.CustomHeaderToken,
  headerName: "x-browser-use-api-key",
  instructionsUrl: "https://cloud.browser-use.com/settings",
});
```

## Environment variables

Local development only:

```env
BROWSER_USE_API_KEY=your_browser_use_api_key
```

For the real production Pack install, the secret is stored and managed by Superhuman through the Pack's authentication flow. The API key is then attached automatically as the `x-browser-use-api-key` header.

## Installation instructions

1. Create or open the Pack in your Superhuman Pack tooling.
2. Upload this repository's `pack.ts`.
3. Install the Pack inside your Superhuman account.
4. Connect a Browser Use API key generated at `https://cloud.browser-use.com/settings`.
5. Use the MCP-backed Browser Use tools from within Superhuman Go.

## Testing instructions

### TypeScript validation

```bash
npm install
npm run build
```

### Manual runtime validation

1. Open the Pack in Superhuman Go.
2. Trigger `tools/list` or any Browser Use tool through the Pack.
3. Confirm the Browser Use tool set is exposed.
4. Run a real browse task using the attached Browser Use key.

## Troubleshooting

### 401 Unauthorized

Usually means the Browser Use API key is missing, expired, or the header is not exactly `x-browser-use-api-key`.

### 403 / network denied

The Pack must include `api.browser-use.com` in `pack.addNetworkDomain(...)`.

### Tools do not appear

The MCP server may not have been refreshed or the Pack may need to be re-uploaded and reinstalled.

### Long-running tasks

The MCP block is not a live streaming channel. Start a browser task and poll for status rather than waiting for a single blocking call.

## SDK limitations and workarounds

- One MCP server per Pack: keep this Pack dedicated to Browser Use.
- Tool-only support: use the Browser Use MCP tools, not MCP resources/prompts.
- No local MCP endpoints: Browser Use must be reached over HTTPS.
- No live streaming: poll via status endpoints when tasks run for a while.
- Static API key config: this is valid for Browser Use, but if Browser Use changes to a different auth scheme later, the Pack auth block would have to be updated.

## Notes

This is a proof-of-concept intended to be installable into a personal Superhuman account. It is the closest viable design to Browser Use's cloud MCP server and should be treated as a working foundation for further hardening.
