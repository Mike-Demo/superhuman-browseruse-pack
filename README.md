# Superhuman Browser Use Pack

This repository contains a production-oriented proof-of-concept Superhuman Pack that connects Superhuman Go to Browser Use Cloud using Browser Use's MCP server.

## Purpose

The Pack exposes Browser Use's browser automation capability directly to Superhuman Go through Browser Use's MCP endpoint. It is designed to be installed into a personal Superhuman account and connected to a Browser Use API key generated in the Browser Use Cloud dashboard.

## Architecture overview

Browser Use exposes an MCP server at:

- `https://api.browser-use.com/v3/mcp`

The server expects a Browser Use API key in the custom HTTP header:

- `x-browser-use-api-key`

The Superhuman Packs SDK supports:

- `pack.addMCPServer(...)` for external MCP connections
- `pack.setUserAuthentication(...)` for Custom Header Token auth
- `pack.addNetworkDomain(...)` for allow-listing public domains

This makes the integration a direct, hosted MCP connection without needing a custom proxy service.

## Why the architecture is valid

The integration is viable because:

1. Superhuman Packs supports MCP server connections.
2. Browser Use Cloud exposes a public MCP endpoint.
3. Browser Use Cloud auth is a static API key in a custom header.
4. Superhuman's `CustomHeaderToken` auth flow matches the Browser Use API key pattern.

## Required configuration

### Browser Use MCP endpoint

```ts
pack.addMCPServer({
  name: "Browser Use",
  endpointUrl: "https://api.browser-use.com/v3/mcp",
});
```

### Browser Use header auth

```ts
pack.setUserAuthentication({
  type: sdk.AuthenticationType.CustomHeaderToken,
  headerName: "x-browser-use-api-key",
  instructionsUrl: "https://cloud.browser-use.com/settings",
  getConnectionName: async (context) => {
    try {
      const response = await context.fetcher.fetch({
        method: "GET",
        url: "https://api.browser-use.com/v3/me",
      });

      return response.body?.email ?? response.body?.name ?? "Browser Use account";
    } catch (_error) {
      return "Browser Use account";
    }
  },
});
```

### Network allow-list

```ts
pack.addNetworkDomain("api.browser-use.com");
pack.addNetworkDomain("cloud.browser-use.com");
```

## Environment variables

This repo includes a local-only env placeholder:

```env
BROWSER_USE_API_KEY=replace_me
```

In the live Superhuman Pack experience, the secret is not read from `.env`; instead, Superhuman stores the API key as part of the Pack's `CustomHeaderToken` auth flow and injects it on outgoing requests as `x-browser-use-api-key`.

## Setup instructions

1. Generate a Browser Use API key from the Browser Use Cloud dashboard:
   - `https://cloud.browser-use.com/settings`
2. Install this Pack into your Superhuman account.
3. When prompted for credentials, paste the Browser Use API key.
4. Confirm the Pack is connected and Browser Use tools are discoverable in Superhuman Go.
5. Use natural-language prompts to have the agent run browser automation tasks.

## Installation flow

1. Upload `pack.ts` using your Superhuman Pack tooling.
2. Ensure the Pack includes `api.browser-use.com` and `cloud.browser-use.com` in its allow-list.
3. Connect with a Browser Use API key.
4. Open Superhuman Go and verify the Browser Use MCP tools appear.
5. Run a basic task such as: "Open example.com and tell me the page title."

## Troubleshooting

### 401 Unauthorized

Cause: the Browser Use key is missing, invalid, expired, or the header name is wrong.

Fix:

- regenerate the Browser Use API key in `https://cloud.browser-use.com/settings`
- confirm the custom header name is exactly `x-browser-use-api-key`
- reconnect the Pack in Superhuman

### 403 / network denied

Cause: the Pack did not allow-list the Browser Use domains.

Fix:

- ensure `api.browser-use.com` and `cloud.browser-use.com` are added with `pack.addNetworkDomain(...)`

### Tools do not appear in Superhuman Go

Cause: the Pack was not uploaded or refreshed, or the MCP server did not finish discovery.

Fix:

- re-upload the Pack
- reinstall or reconnect the Pack in Superhuman
- confirm the Browser Use MCP endpoint is reachable

### Long-running tasks time out

Cause: MCP requests are request/response based and do not stream live events.

Fix:

- run the task and poll for status using `GetBrowserTaskStatus`
- do not expect a single request to stay open for entire browser automation sequences

## SDK limitations and workarounds

- One MCP server per Pack: this Pack is intentionally dedicated to Browser Use only.
- MCP tool exposure only: the Pack exposes Browser Use tools, not arbitrary resources or prompts.
- Public HTTPS endpoint required: this must be a hosted server, not a local port.
- No live streaming: use polling for long-running tasks.
- Browser Use auth scheme may evolve: if Browser Use changes from API-key header auth to a different mechanism, the auth block must be updated.

## Summary

This is a direct, working proof-of-concept for connecting Superhuman Go to Browser Use Cloud through Browser Use's hosted MCP server. It is intentionally minimal, installation-friendly, and ready to use as a base for a production Pack implementation.
